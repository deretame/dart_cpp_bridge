# Codegen Dart 生成结构重构设计

> 状态：草案，待评审  
> 更新日期：2026-07-25

---

## 1. 背景与目标

当前 codegen 在 `native_gen/` 下生成三个文件：

```
native_gen/
├── api.g.dart    # BridgeApiImpl（method id + wire 编解码）+ enum/data_class 定义
├── api.dart      # BridgeApi 单例 facade + opaque class wrapper（如 Counter）
└── api_fn.dart   # 顶层函数（initBridge / disposeBridge / 各 API 函数）
```

**问题**：
- 所有 API 混在一起，无法按业务模块拆分
- 函数使用位置参数，调用时可读性差
- 与 FRB 的生成结构差异较大，迁移成本高

**目标**：
- 模仿 FRB 的生成结构，按源码头文件拆分 Dart 文件
- 函数统一使用命名参数 `{required ...}`
- 严格遵循 Dart 命名规范
- 提供清晰的分层：wire impl → 管理类 → 业务 API

---

## 2. 新生成结构

```
native_gen/
├── dcb_generated.dart       # 基础层：BridgeApiImpl 单例 + enum + wire 编解码
└── api/
    ├── init.dart            # 管理类：DcbLib（init / dispose / shutdown）
    ├── bridge_api.dart      # 来自 bridge_api.h：顶层函数 + Point/Rect/OrderStatus
    └── counter.dart         # 来自 counter.h：Counter opaque class
```

### 2.1 文件与源头映射

| C++ 头文件 | 生成 Dart 文件 | 内容 |
|-----------|---------------|------|
| （全局） | `dcb_generated.dart` | BridgeApiImpl 单例、所有 enum 定义、wire 编解码 helper |
| （全局） | `api/init.dart` | DcbLib 管理类 |
| `bridge_api.h` | `api/bridge_api.dart` | 该头文件中的顶层函数 + 该头文件中定义的 data_class/enum |
| `counter.h` | `api/counter.dart` | Counter opaque class wrapper |

**规则**：
- 每个被扫描的 C++ 头文件生成一个对应的 Dart 文件
- 文件名：C++ 头文件名转 snake_case（`bridge_api.h` → `bridge_api.dart`）
- 类定义跟随其定义所在的头文件

## 3. 各文件详细设计

### 3.1 `dcb_generated.dart`（基础层）

```dart
// GENERATED by dart_cpp_bridge codegen — do not edit.
// ignore_for_file: unused_element

import 'dart:async';
import 'dart:typed_data';
import 'package:dart_cpp_bridge/dart_cpp_bridge.dart';

// ═══════════════════════════════════════════
// Enums
// ═══════════════════════════════════════════

enum OrderStatus { created, paid, shipped }

// ═══════════════════════════════════════════
// Wire Helpers (private)
// ═══════════════════════════════════════════

void _writePoint(ByteWriter w, Point v) { ... }
Point _readPoint(ByteReader r) { ... }

// ═══════════════════════════════════════════
// BridgeApiImpl (wire-level, singleton)
// ═══════════════════════════════════════════

final class BridgeApiImpl {
  BridgeApiImpl._(this.bridge);

  final DartCppBridge bridge;

  // ── 单例 ──
  static BridgeApiImpl? _instance;
  static BridgeApiImpl get instance {
    final i = _instance;
    if (i == null) throw StateError('DcbLib.init() must be called first');
    return i;
  }
  static void _init(DartCppBridge bridge) => _instance = BridgeApiImpl._(bridge);
  static void _dispose() => _instance = null;

  // ── Method IDs ──
  static const int addId = 513277594;
  static const int bridgeVersionId = 513280939;
  // ...

  // ── Wire Methods ──
  Future<int> add(int a, int b) async { ... }
  int bridgeVersion() { ... }
  // ...
}
```

**要点**：
- `BridgeApiImpl` 改为单例模式，通过 `BridgeApiImpl.instance` 访问
- 单例由 `DcbLib.init()` 内部初始化，外部不直接构造
- enum / wire helper 全部放在此文件（全局共享）；data_class 定义跟随其头文件对应的 API 文件

### 3.2 `api/init.dart`（管理类）

```dart
// GENERATED by dart_cpp_bridge codegen — do not edit.

import 'package:dart_cpp_bridge/dart_cpp_bridge.dart';
import '../dcb_generated.dart';

/// dart_cpp_bridge 管理类。
///
/// 使用方式：
/// ```dart
/// await DcbLib.init(libraryPath: '...');
/// final v = bridgeVersion();
/// DcbLib.shutdown(); // 仅进程退出时
/// ```
final class DcbLib {
  DcbLib._();

  static DartCppBridge? _bridge;

  /// 是否已初始化。
  static bool get isInitialized => _bridge != null;

  /// 底层 bridge 实例（初始化后可用）。
  static DartCppBridge get bridge {
    final b = _bridge;
    if (b == null) throw StateError('DcbLib.init() must be called first');
    return b;
  }

  /// 初始化（每个 Isolate 调用一次）。
  static Future<void> init({String? libraryPath}) async {
    if (_bridge != null) return;
    final b = await DartCppBridge.init(libraryPath: libraryPath);
    _bridge = b;
    BridgeApiImpl._init(b);  // 初始化单例
  }

  /// 关闭当前 Isolate 的 session（可选，Finalizer 也会自动关闭）。
  static void dispose() {
    _bridge?.dispose();
    _bridge = null;
    BridgeApiImpl._dispose();
  }

  /// 进程级 shutdown（仅主 Isolate / App 退出时调用）。
  static void shutdown() {
    _bridge?.shutdown();
    _bridge = null;
    BridgeApiImpl._dispose();
  }
}
```

**要点**：
- 类名 `DcbLib`（Dart-Cpp Bridge Library 缩写，可配置）
- 纯静态方法，无需实例化
- 负责初始化 `BridgeApiImpl` 单例

### 3.3 `api/bridge_api.dart`（业务 API）

```dart
// GENERATED by dart_cpp_bridge codegen — do not edit.
// Source: native/api/bridge_api.h

import 'dart:async';
import '../dcb_generated.dart';

export '../dcb_generated.dart' show OrderStatus;

// ═══════════════════════════════════════════
// Data classes（定义在本文件，跟随源码头文件）
// ═══════════════════════════════════════════

final class Point {
  const Point({required this.x, required this.y});
  final double x;
  final double y;
  // == / hashCode ...
}

final class Rect { ... }

// ═══════════════════════════════════════════
// Functions
// ═══════════════════════════════════════════

/// sync → int bridgeVersion()
int bridgeVersion() => BridgeApiImpl.instance.bridgeVersion();

/// async → Future<int> add(int a, int b)
Future<int> add({required int a, required int b}) =>
    BridgeApiImpl.instance.add(a, b);

/// async → Future<int> sumScores(Map<String, int> scores)
Future<int> sumScores({required Map<String, int> scores}) =>
    BridgeApiImpl.instance.sumScores(scores);

/// stream → Stream<int> tickStream(int? count, int? intervalMs)
/// C++ 侧有默认值，Dart 侧为 optional (T?)，不加 required
Stream<int> tickStream({int? count, int? intervalMs}) =>
    BridgeApiImpl.instance.tickStream(count, intervalMs);

/// 元组返回值示例：(int, String) getUserInfo(int id)
/// 元组作为整体是一个命名参数，必选加 required
(int, String) getUserInfo({required int id}) =>
    BridgeApiImpl.instance.getUserInfo(id);

/// async + DartFn
Future<String> greetDartFn({
  required Future<String> Function(String) callback,
  required String name,
}) =>
    BridgeApiImpl.instance.greetDartFn(callback, name);

// ... 其他函数
```

**要点**：
- 参数规则：
  - 必选参数（非 optional）：加 `required` → `{required int a}`
  - 可选参数（C++ 侧有默认值，Dart 侧为 `T?`）：不加 `required` → `{int? count}`
  - 无参数函数：不加 `{}`，直接 `()`
  - 元组（多返回值）：整个元组作为一个命名参数，规则同上（必选加 `required`，可选不加）
- 通过 `export` 重新导出该头文件中定义的 enum/data_class
- 函数直接调用 `BridgeApiImpl.instance.xxx()`

### 3.4 `api/counter.dart`（Opaque Class）

```dart
// GENERATED by dart_cpp_bridge codegen — do not edit.
// Source: native/api/counter.h

import 'dart:async';
import 'package:dart_cpp_bridge/dart_cpp_bridge.dart';
import '../dcb_generated.dart';
import 'init.dart';

/// Opaque wrapper for `demo::api::Counter`.
final class Counter extends CppOpaqueInterface {
  Counter._({required super.bridge, required super.handle});

  // ── Constructors (factory) ──

  /// BRIDGE_CONSTRUCTOR Counter()
  factory Counter() => Counter._(
        bridge: DcbLib.bridge,
        handle: BridgeApiImpl.instance.counterNew(),
      );

  /// BRIDGE_CONSTRUCTOR Counter(std::int32_t initialValue)
  factory Counter.int32T({required int initialValue}) => Counter._(
        bridge: DcbLib.bridge,
        handle: BridgeApiImpl.instance.counterNewInt32T(initialValue),
      );

  // ── Instance Methods ──

  Future<int> value() async {
    ensureAlive();
    return await BridgeApiImpl.instance.counterValue(handle);
  }

  int valueSync() {
    ensureAlive();
    return BridgeApiImpl.instance.counterValueSync(handle);
  }

  Future<void> increment({int delta = 1}) async {
    ensureAlive();
    await BridgeApiImpl.instance.counterIncrement(handle, delta);
  }

  Future<Counter> duplicate() async {
    ensureAlive();
    final newHandle = await BridgeApiImpl.instance.counterDuplicate(handle);
    return Counter._(bridge: DcbLib.bridge, handle: newHandle);
  }

  // ── Static Methods ──

  static int sum({required int a, required int b}) =>
      BridgeApiImpl.instance.counterSum(a, b);

  static int aliveCount() => BridgeApiImpl.instance.counterAliveCount();
}
```

**要点**：
- 类名保持 PascalCase（`Counter`）
- 实例方法参数也改为命名参数（规则同 §3.3）
- 通过 `DcbLib.bridge` 获取 bridge 实例
- 通过 `BridgeApiImpl.instance` 调用 wire 方法

#### 3.4.1 构造函数命名规则

多个 `BRIDGE_CONSTRUCTOR` 映射为 Dart `factory` 构造函数，命名规则：

| C++ 构造函数 | Dart factory 名 | 说明 |
|-------------|----------------|------|
| `Counter()` | `Counter()` | 无参构造 → 默认 factory |
| `Counter(std::int32_t initialValue)` | `Counter.int32T(...)` | 类名 + 参数类型签名 |
| `Counter(std::string name, int32_t age)` | `Counter.stringInt32T(...)` | 多参数类型拼接 |

**类型签名映射**（C++ 类型 → factory 名后缀）：

| C++ 类型 | 签名片段 |
|----------|----------|
| `std::int32_t` / `int32_t` | `Int32T` |
| `std::int64_t` / `int64_t` | `Int64T` |
| `std::uint32_t` | `Uint32T` |
| `double` | `Double` |
| `float` | `Float` |
| `std::string` | `String` |
| `bool` | `Bool` |
| 自定义类 `Point` | `Point` |

- 无参构造函数：直接作为默认 `factory ClassName()`
- 有参构造函数：`factory ClassName.<typeSig>(...)`，参数使用命名参数（规则同 §3.3）
- 所有构造函数生成为 `factory`（因为需要调用 wire 获取 handle）

## 4. 命名规范

| 元素 | 规范 | 示例 |
|------|------|------|
| 类名 | PascalCase | `Counter`, `Point`, `OrderStatus` |
| 函数名 | camelCase | `bridgeVersion`, `sumScores`, `tickStream` |
| 文件名 | snake_case | `bridge_api.dart`, `counter.dart`, `init.dart` |
| 参数名 | camelCase | `initialValue`, `intervalMs` |
| 常量 | camelCase | `addId`, `bridgeVersionId` |

### 4.1 C++ → Dart 名称转换

```python
# 函数名：snake_case → camelCase
def _dart_fn_name(cpp_name: str) -> str:
    # bridge_version → bridgeVersion
    # sum_scores → sumScores
    parts = cpp_name.split('_')
    return parts[0] + ''.join(p.capitalize() for p in parts[1:])

# 类名：保持 PascalCase（C++ 类名通常已是）
def _dart_class_name(cpp_name: str) -> str:
    return cpp_name  # Counter → Counter

# 文件名：C++ 头文件名直接转 .dart
def _dart_file_name(header_name: str) -> str:
    # bridge_api.h → bridge_api.dart
    # counter.h → counter.dart
    return header_name.replace('.h', '.dart').replace('.hpp', '.dart')
```

## 7. 已确认决策

| 问题 | 决策 |
|------|------|
| 管理类名 | `DcbLib`（Dart-Cpp Bridge Library） |
| enum/data_class 位置 | enum 放 `dcb_generated.dart`；data_class 定义跟随头文件对应的 API 文件（codec helper 仍在 impl 文件，通过 import 引用类型） |
| 无参数函数 | 不加 `{}`，直接 `()` |
| optional 参数 | Dart 侧为 `T?`，不加 `required` |
| 元组参数 | 整个元组作为一个命名参数，必选加 `required`，可选不加 |
| opaque class 构造 | 生成为 `factory`，多构造函数通过类型签名后缀区分 |
| data_class toString | 默认自动生成 `toString()`（如 `Point(x: $x, y: $y)`）；可用 YAML `dart_code` 注入自定义 Dart 代码覆盖 |
| opaque class toString | 用 `BRIDGE_TO_STRING` 标记一个同步方法（返回 `std::string`、无参、非静态），生成 Dart `toString()` override |
| 迁移兼容 | 不需要（库未发布，无用户） |

## 8. toString 支持

数据类与不透明类的状态可见性不同，因此采用两套机制：

### data_class：默认 toString + YAML `dart_code`

所有 data_class 自动生成标准 `toString()`，无需配置：

```dart
@override
String toString() => 'Point(x: $x, y: $y)';
```

需要定制时，在 `dart_cpp_bridge.yaml` 中按类名注入任意 Dart 代码（原样插入类体末尾，并禁用默认 toString）。C++ 没有过程宏，Dart 代码放在 YAML 多行块标量中比塞进 C++ 字符串更合理：

```yaml
dart_code:
  Rect: |
    @override
    String toString() => 'Rect[$topLeft -> $bottomRight]';
```

### opaque_class：`BRIDGE_TO_STRING` 宏

不透明类的状态在 C++ 侧，纯 Dart 的 toString 无法访问，因此指定一个 C++ 方法走 wire 调用：

```cpp
class BRIDGE_OPAQUE Counter {
 public:
  BRIDGE_TO_STRING std::string toString() const;
};
```

约束（parser 校验，违反则 codegen 报错）：必须是同步实例方法、无参数、返回 `std::string`、非 `Lazy`、每类至多一个。生成效果：

```dart
@override
String toString() => BridgeApiImpl.instance.counterToString(this);
```

impl 内部照常 `ensureAlive()`，对已 dispose 的对象调用 toString 会抛 `StateError`（与其他方法一致）。
